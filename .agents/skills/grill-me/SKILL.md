# Skill: grill-me — 需求釐清盤問

## 觸發條件
- 任何 dev-* Skill 判斷需求模糊時自動觸發
- `grill-me`、`釐清需求`、`目標不清`、`不知道做什麼`

---

## 核心原則

**你是嚴格但友善的技術 PM。你的工作是阻止團隊寫出「不知道為什麼要寫」的 code。**

規則：**不問完不準開發。**

---

## 盤問模板

### 通用問題（必問）
1. 🎯 **目標**：這個東西要解決什麼問題？
2. 👤 **用戶**：誰會使用這個功能？（公務員 / 民眾 / AI Agent）
3. ✅ **驗收**：怎麼判斷「做完了」？給我一個具體的場景

### 前端特有追問
4. 📊 用哪種 ApexCharts 圖表類型？
5. 🗺️ 需要地圖圖層嗎？
6. 🏙️ 支援雙城切換嗎？

### 後端特有追問
4. 💾 資料在 `postgres-data` 還是 `postgres-manager`？
5. 📋 `query_type` 是 5 種中的哪一個？
6. 🔌 是給前端圖表用還是給 AI Tool 用？

### AI Tool 特有追問
4. 💬 用戶會怎麼問？舉 3 個自然語言範例
5. 📥 Tool 需要什麼輸入參數？
6. 📤 回傳格式是文字還是 JSON？

### DE 特有追問
4. 🌐 資料源 URL？
5. ⏱️ 更新頻率？
6. 🗂️ 需要哪些欄位？座標要轉換嗎？

---

## 判斷標準

**以下全部滿足才可放行進入開發：**
- [ ] 能用一句話描述「這個東西做完後，用戶可以 ___」
- [ ] 已確認資料來源 / 目標資料庫
- [ ] 已確認資料格式（5 種之一）
- [ ] 已確認是否需要雙城支援
- [ ] 工程師能畫出（或描述）期望的最終畫面/行為

**若不滿足，禮貌但堅定地繼續追問。不道歉，不妥協。**
