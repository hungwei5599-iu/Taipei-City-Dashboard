Taipei Dashboard

這個系統是怎麼運作的

從「你要新增一個組件」出發，理解 FE、BE、DE 與資料庫的全貌

核心概念：Configuration-Driven 架構

傳統做法：每新增一個組件 → 寫一個新的 Vue 元件 + 寫一個新的 BE API + 寫 SQL。
這個專案的做法：所有顯示邏輯都參數化存在資料庫裡，程式碼本身是通用的框架。

❌ 傳統做法（你原本想的）

加 YouBike 組件：寫 YouBike.vue + GET /youbike + YouBike SQL

加急診組件：寫 ErRoom.vue + GET /er-room + ER SQL

每次都要改程式碼、重新部署

✅ 本專案做法（Configuration-Driven）

一個通用容器 DashboardComponent.vue 渲染所有組件

一個通用 API GET /component/:id/chart 服務所有組件

加新組件只需在 DB 插入設定資料

四個層次各自做什麼

① DE（資料工程）

Airflow 定時抓外部 API → 清洗資料 → 存入 postgres-data

負責讓「原始資料」定期更新到資料庫。例如每 5 分鐘抓一次 NHI 急診 API。

② postgres-data（業務資料庫）

存放真實的業務數據：急診等候人數、YouBike 站點、空氣品質等。

由 DE 自動寫入，BE 執行 SQL 時從這裡讀。

③ postgres-manager（設定資料庫）

存放組件的顯示設定：用什麼圖表、執行什麼 SQL、地圖怎麼畫。

手動設定一次，之後不變。BE 讀這裡的 SQL 字串去查 postgres-data。

④ BE（後端 Go/Gin）

通用 SQL 執行器。從 postgres-manager 拿到 SQL 字串，到 postgres-data 執行，回傳 JSON 給 FE。

不需要為新組件改任何 Go 程式碼。

⑤ FE（前端 Vue 3）

通用渲染框架。DashboardComponent.vue 是所有組件的容器，根據設定自動選擇圖表類型。

不需要為新組件新建任何 .vue 檔案。

一個請求的完整旅程

1

使用者打開 Dashboard

FE 發出 GET /api/v1/dashboard/taipei_health，取得這個 Dashboard 包含哪些組件 ID（來自 postgres-manager.dashboards）

2

FE 取得組件清單

BE 回傳組件清單（含 id、名稱、圖表設定、地圖設定）。FE 存進 contentStore.currentDashboard.components

3

DashboardView.vue 的 v-for 執行

清單裡有幾個組件，畫面就出現幾個「正方形」。每個正方形都是同一個 DashboardComponent.vue 的實例，只是傳入不同的 config。

4

FE 為每個組件抓圖表數據

對每個組件呼叫 GET /api/v1/component/:id/chart?city=taipei

5

BE 查 postgres-manager 取得 SQL 字串

從 query_charts 表撈出對應的 SQL 字串和 query_type

6

BE 把 SQL 字串丟進 postgres-data 執行

根據 query_type 決定用哪個解析函式（two_d / three_d / time / map_legend）

7

FE 收到 JSON 資料，渲染圖表

DashboardComponent 讀取 chart_config.types[0]（例如 "BarChart"），動態渲染對應的圖表元件

兩個資料庫的職責

比較項目 postgres-data（port 5433） postgres-manager（port 5432）
儲存什麼 實際業務資料（急診人數、YouBike 數量） 組件顯示設定（SQL 字串、圖表類型、地圖設定）
誰在寫入 DE（Airflow）自動定期寫入 你手動執行 INSERT SQL 一次
資料量變化 隨時間增加或被 replace 基本固定，只有管理員手動改
類比 倉庫裡的貨物 說明書＋展示規則

function returnChartComponent(name, svg) {
  switch (name) {
    case "BarChart":          return svg ? BarChartSvg : BarChart;
    case "ColumnChart":       return svg ? ColumnChartSvg : ColumnChart;
    case "DonutChart":        return svg ? DonutChartSvg : DonutChart;
    case "TimelineSeparateChart": return svg ? ... : TimelineSeparateChart;
    case "BarPercentChart":   return svg ? ... : BarPercentChart;
    case "GuageChart":        return svg ? ... : GuageChart;
    case "RadarChart":        return svg ? ... : RadarChart;
    case "HeatmapChart":      return svg ? ... : HeatmapChart;
    // ... 共 20+ 種
    default: return MapLegend;
  }
}

圖表資料格式對應（query_type）

query_type SQL 必須有的欄位 適合圖表 急診組件建議
two_d x_axis（文字）, data（數字） BarChart, ColumnChart ✅ 醫院名 vs 一般候診人數
three_d x_axis, y_axis, data BarChart（分組） ✅ 醫院名 × 等候類別 × 人數
percent x_axis, y_axis, data BarPercentChart, DonutChart 可用於顯示各類別占比
time x_axis（時間）, y_axis, data TimelineSeparateChart 有 history_table 時使用
map_legend name, type, value MapLegend 地圖圖例

func GetComponentChartDataQuery(id int, city string) (queryType, queryString string, err error) {
  var chartDataQuery ChartDataQuery

  err = DBManager.                         ← 連接 postgres-manager
    Table("components").
    Select("query_charts.query_type, query_charts.query_chart").

DE（資料工程）深入解析

Airflow DAG 的結構、job_config.json 的設定，以及 load_behavior 的意義

DE 在整個架構中的位置

DE 是唯一需要寫新程式碼的部分。因為每個外部 API 的格式都不同，清洗邏輯無法通用化。 DE 的職責：定時抓外部資料 → 清洗 → 存進 postgres-data。跟 FE、BE、postgres-manager 完全無關。

load_behavior 三種模式

值 行為 適用場景
replace 每次執行前清空整張表，再寫入新資料 即時資料（急診等候、YouBike 站點）
append 保留原有資料，把新資料加在後面 歷史累積資料（月報、陳情記錄）
upsert 有就更新，沒有就新增（用主鍵判斷） 需要更新特定記錄

急診組件用 replace：每次跑 DAG 就把舊的 21 筆蓋掉，寫入最新的 21 筆。

from airflow import DAG
from operators.common_pipeline import CommonDag


def _transfer(**kwargs):
    import pandas as pd
    import requests
    from sqlalchemy import create_engine
    from utils.load_stage import (
        save_dataframe_to_postgresql,
        update_lasttime_in_data_to_dataset_info,
    )
    from utils.transform_time import convert_str_to_time_format

    # ── Config ──
    dag_infos = kwargs.get("dag_infos")
    ready_data_db_uri = kwargs.get("ready_data_db_uri")
    dag_id = dag_infos.get("dag_id")
    load_behavior = dag_infos.get("load_behavior")
    default_table = dag_infos.get("ready_data_default_table")

    # ── Extract ──
    res = requests.post(
        "https://info.nhi.gov.tw/api/inae4000/inae4001s01/SQL0002",
        json={},
        timeout=30,
    )
    res.raise_for_status()
    raw_data = pd.DataFrame(res.json()["data"])

    # ── Transform ──
    data = raw_data[raw_data["areA_NO_N"].isin(["01", "31"])].copy()
    data = data.rename(columns={
        "hosP_ID":            "hosp_id",
        "hosP_NAME":          "hosp_name",
        "areA_NO_N":          "area_code",
        "conT_TYPE":          "cont_type",
        "waiT_SEE_CNT":       "wait_see",
        "waiT_BED_CNT":       "wait_bed",
        "waiT_GENERAL_CNT":   "wait_general",
        "waiT_ICU_CNT":       "wait_icu",
        "txT_DATE":           "data_time",
    })
    # 數字欄位轉 int，null 保留為 None（DB 接受）
    for col in ["wait_see", "wait_bed", "wait_general", "wait_icu"]:
        data[col] = pd.to_numeric(data[col], errors="coerce").astype("Int64")

    data["data_time"] = convert_str_to_time_format(data["data_time"])
    ready_data = data[[
        "hosp_id", "hosp_name", "area_code", "cont_type",
        "wait_see", "wait_bed", "wait_general", "wait_icu", "data_time",
    ]]

    # ── Load ──
    engine = create_engine(ready_data_db_uri)
    save_dataframe_to_postgresql(
        engine,
        data=ready_data,
        load_behavior=load_behavior,
        default_table=default_table,
    )
    update_lasttime_in_data_to_dataset_info(engine, dag_id, data["data_time"].max())


dag = CommonDag(proj_folder="proj_city_dashboard", dag_folder="er_room_realtime")
dag.create_dag(etl_func=_transfer)
