🔐 認證與授權 (Auth)

JWT 是什麼、兩種登入方式如何運作、使用者權限如何控制——完整的身份驗證機制說明。

認證 vs 授權：兩個不同的概念

🪪 認證（Authentication）= 你是誰？

驗證使用者的身份。就像進入辦公室要刷門禁卡——系統確認「這是某某人」。

方式：Email + 密碼，或台北通 OAuth

🔑 授權（Authorization）= 你能做什麼？

確認使用者有哪些權限。就像辦公室不同員工能進不同房間——管理員可以修改元件，一般用戶只能查看。

方式：RBAC 角色權限控制

JWT Token：無狀態的身份證

JWT（JSON Web Token）是一種不需要伺服器記住登入狀態的身份驗證方式。Token 本身就包含了所有必要資訊。

💡 類比：JWT 就像演唱會的電子票券。票上印了你的名字、座位、有效日期，工作人員掃描後直接知道一切，不需要每次都查後台資料庫。但如果票被偷了，小偷也可以進場——所以要設定過期時間。

// Payload 解碼後的內容（使用者資訊）

// Signature = HMAC-SHA256(Header + "." + Payload, JWT_SECRET)
// JWT_SECRET 只有伺服器知道，確保 Token 無法偽造

每個請求如何驗證身份

登入後，前端的每一個 API 請求都會帶著 JWT Token：

// 前端發送請求時自動帶上 Token（axios 攔截器）
GET /api/v1/component/123/chart
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VyX2lkIjo0Mn0...


// 後端中介軟體驗證 Token
func ValidateJWT(c *gin.Context) {
  tokenString := 從Header取出Bearer後的部分
  
  token, err := jwt.ParseWithClaims(tokenString, &claims{},
    func(token *jwt.Token) (interface{}, error) {
      return []byte(os.Getenv("JWT_SECRET")), nil
    })
  
  if err != nil || !token.Valid {
    c.JSON(401, "Unauthorized")
    c.Abort()
    return
  }
  // Token 有效，把使用者資訊存進 context 繼續
  c.Set("userID", claims.UserID)
  c.Next()
}

角色與權限系統（RBAC）

系統使用「群組 + 角色」的組合來控制存取權限：

群組 角色 可以看到的儀表板 說明
public viewer 公開儀表板 所有人（包含未登入）
taipei viewer 台北市相關儀表板 白名單使用者（市府員工）
personal editor 個人自訂儀表板 登入後的一般使用者
admin admin 全部 + 管理功能 is_admin = true 的管理員
💡 密碼安全性：bcrypt
使用者的密碼不是明文儲存在資料庫裡，而是用 bcrypt 演算法雜湊後儲存。bcrypt 的特點是：
1. 同樣的密碼每次產生不同的 hash（加鹽，Salt）
2. 計算很慢（故意的）——讓暴力破解不可行
3. 就算資料庫被盜，攻擊者也很難還原密碼
