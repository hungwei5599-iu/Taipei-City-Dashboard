⚙️ 後端 (Backend)

Go 語言 + Gin 框架的 API 伺服器——每個請求如何被接收、驗證、處理、然後回傳資料的完整過程。

後端的核心工作是什麼？

後端就是前端和資料庫之間的中間人。它做三件事：

🔐
驗證身份
確認「你是誰」有沒有權限做這件事
📊
查詢資料
從資料庫取出需要的資料
📤
格式化回傳
把資料整理成 JSON 格式回給前端
💡 類比：後端就像銀行的「窗口行員」。你（前端）帶著身份證（JWT Token）來辦理業務，行員先確認你的身份，然後查帳戶（資料庫），再把你要的結果告訴你。

架構設計：MVC 模式

後端採用 MVC（Model-View-Controller） 模式，把職責分開：

📋 Model（模型）

定義資料結構，負責和資料庫溝通

→ 定義 Go struct（資料結構）
→ 包含資料庫查詢方法
→ 用 GORM ORM 操作 DB

🎯 Controller（控制器）

處理 HTTP 請求，協調 Model 和回應

→ 解析請求參數
→ 呼叫 Model 查資料
→ 回傳 JSON 回應

🛣️ Router（路由）

設定 URL 路徑對應哪個控制器

→ 定義 API 端點
→ 套用中介軟體
→ 分組路由管理

關鍵程式碼：app.go 啟動流程

// app/app.go 的啟動順序（簡化）
func InitApp() {
  // 1. 連線到兩個 PostgreSQL 資料庫
  models.ConnectToDB()
  
  // 2. 連線到 Redis
  cache.ConnectToRedis()
  
  // 3. 啟動排程任務（cron jobs）
  initial.InitCron()
  
  // 4. 初始化 ONNX 嵌入模型（AI 向量搜尋用）
  initLMSession()
  
  // 5. 建立 Gin 路由器
  router := gin.New()
  
  // 6. 套用全局中介軟體
  router.Use(middleware.Cors())
  
  // 7. 設定所有路由
  routes.SetupRoutes(router)
  
  // 8. 開始監聽 HTTP 請求
  router.Run(":8080")
}

中介軟體是每個請求都會經過的「關卡」，在控制器執行前先做一些通用處理：

🔐 JWT 驗證中介軟體

// 簡化邏輯
func ValidateJWT() {
  token := 從 Header 取出 Token

    把使用者資訊存入 context

GORM：用 Go 物件操作資料庫

GORM 是 Go 的 ORM（Object-Relational Mapping）工具，讓你不需要寫原始 SQL，直接用 Go 結構體操作資料庫：

// 定義資料結構（Model）
type AuthUser struct {
  ID uint `gorm:"primaryKey"`
  Name string `gorm:"column:name"`
  Email string `gorm:"column:email"`
  Password string `gorm:"column:password"`
  IsAdmin bool `gorm:"column:is_admin"`
}

// 查詢（自動產生 SQL: SELECT * FROM auth_users WHERE id=?）
var user AuthUser
global.MANAGER_DB.First(&user, userID)

// 建立（自動產生 SQL: INSERT INTO...）
global.MANAGER_DB.Create(&newUser)
💡 為什麼用兩個資料庫？
postgres-manager：存使用者帳號、儀表板設定、元件元資料——這些變動少、查詢複雜
postgres-data：存圖表的實際數據——這些資料量大、更新頻繁（Airflow 每天寫入）
分開可以讓兩個資料庫獨立擴展和優化，不會互相影響。
