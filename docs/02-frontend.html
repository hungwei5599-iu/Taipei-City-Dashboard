🖥️ 前端 (Frontend)

Vue 3 應用程式如何把後端資料變成你看到的圖表和地圖——從元件結構、狀態管理、到圖表渲染的完整說明。

前端的技術棧（用了哪些工具）

🏗️ Vue 3 + Vite

主要框架，Composition API 風格，Vite 負責超快的開發建構

📦 Pinia

狀態管理（像一個全局的資料倉庫），取代舊版 Vuex

📡 Axios

HTTP 請求工具，負責跟後端 API 通訊

📊 ApexCharts

繪製各種圖表（長條、折線、圓餅、熱力圖等）

🗺️ Mapbox GL

顯示互動式地圖，支援向量圖磚

🎨 Deck.gl

在地圖上疊加大量資料圖層（熱力、弧線、散點等）

Pinia：前端的「大腦記憶中心」

Pinia 是 Vue 3 的狀態管理工具。簡單說：它就是一個全局的資料倉庫，所有元件都可以存取裡面的資料，不需要層層傳遞 props。

💡 類比：想像 Pinia 是公司的「共享文件系統」。不同部門（元件）需要同一份報告（資料），不需要每個人都各自影印一份，直接去共享文件夾拿就好。

圖表是怎麼畫出來的？

整個圖表渲染流程分成三步驟：

1

後端回傳的 JSON 資料長這樣

// 2D 資料（長條圖/圓餅圖）
[
  { "x_axis": "大安區", "data": 312000 },
  { "x_axis": "信義區", "data": 228000 },
  { "x_axis": "中山區", "data": 197000 }
]

// 時間序列資料（折線圖）
[
  { "timestamp": "2024-01-01", "series_name": "大安區", "value": 312000 },
  { "timestamp": "2024-02-01", "series_name": "大安區", "value": 313500 }
]
2

contentStore 把資料存好，元件讀取

// BarChart.vue 元件內部
const contentStore = useContentStore()

// 從 store 讀取這個元件的資料
const chartData = computed(() => {
  return contentStore.components[props.componentId].chart_data
})
3

ApexCharts 根據資料畫出圖表

// template 中使用 vue3-apexcharts
<apexchart
  type="bar"
  :options="chartOptions" // 圖表樣式設定
  :series="chartSeries" // 實際資料
/>

支援哪些圖表類型？

系統根據元件設定中的 chart_type 決定渲染哪種圖表元件：

📊 BarChart 長條圖 📊 BarChartWithGoal 帶目標長條圖 📊 BarPercentChart 百分比長條圖 📈 ColumnChart 直條圖 📈 ColumnLineChart 直條折線組合 🍩 DonutChart 甜甜圈圖 🌡️ GuageChart 儀表圖 🔥 HeatmapChart 熱力圖 🗺️ DistrictChart 行政區圖 🏷️ ComponentTag 標籤顯示

地圖是怎麼顯示的？

地圖功能用了兩個工具的組合：

🗺️ Mapbox GL — 底圖

提供基礎地圖畫面（街道、建築、地形），需要 Mapbox API Token。透過向量圖磚渲染，速度快且可客製化樣式。

🎨 Deck.gl — 資料圖層

疊加在地圖上的資料視覺化圖層。支援：熱力圖層（HeatmapLayer）、弧線圖層（ArcLayer）、散點圖層（ScatterplotLayer）、GeoJSON 多邊形等。

💡 類比：Mapbox 是地圖的「底紙」（就像 Google Maps），Deck.gl 是貼在上面的「透明貼紙」，上面畫著資料（例如：哪裡空氣品質差就畫紅點）。

路由：9 個頁面

/ → DashboardView（主儀表板）
/map → MapView（地圖視圖）
/component → ComponentView（元件管理）
/component/:id → ComponentInfoView（元件詳情）
/embed/:id → EmbedView（可嵌入其他網站的元件）
/callback → CallBack（OAuth 回調頁）
/admin → AdminDashboard（管理介面）
/admin/user → AdminUser（使用者管理）
/admin/component → AdminEditComponent（元件編輯）

Axios：前端怎麼跟後端說話

所有 API 請求都透過一個統一設定的 Axios 實例，位於 src/router/axios.js：

// 重要設定（簡化版）
const instance = axios.create({
  baseURL: '/api/dev', // 從環境變數讀取
})

// 每個請求自動加上 JWT Token
instance.interceptors.request.use((config) => {
  const token = authStore.token
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// 處理錯誤回應
instance.interceptors.response.use(null, (error) => {
  if (error.response.status === 401) authStore.logout() // 未授權→登出
  if (error.response.status === 429) showRateLimit() // 請求過多→顯示提示
})
💡 為什麼要用攔截器（Interceptors）？如果沒有攔截器，每個 API 呼叫都要手動加 Token 和處理錯誤，重複 code 非常多。攔截器讓這些「每次都要做的事」只寫一次就好，所有請求自動套用。

環境變數

前端透過 .env 檔案設定重要參數，這些值在 Vite 建構時注入：

VITE_API_URL=/api/dev # 後端 API 基底路徑
VITE_MAPBOXTOKEN=pk.xxxx... # Mapbox 地圖 Token
VITE_MAPBOXTILE=mapbox://xxx # Mapbox 圖磚樣式
VITE_TAIPEIPASS_URL=https://... # 台北通 OAuth 網址
VITE_TAIPEIPASS_CLIENT_ID=xxx # 台北通 Client ID
