⚡ Redis 快取與速率限制

Redis 在這個系統中扮演什麼角色、速率限制（Rate Limiting）是怎麼用 Redis 實作的、為什麼要有速率限制。

Redis 是什麼？

Redis 是一個超高速的記憶體資料庫。相比 PostgreSQL 把資料存在硬碟，Redis 把所有資料放在 RAM（記憶體）裡，所以讀寫速度極快（微秒級）。

💡 類比：PostgreSQL 是「圖書館」（資料多、有索引，但找書要走去書架），Redis 是「桌上的便條紙」（一眼就看到，但空間有限、斷電就沒了）。兩者配合使用，速度和容量都兼顧。

Redis 在這個系統中的用途

⚡ 主要用途：速率限制（Rate Limiting）

這是 Redis 在這個系統最重要的功能。防止單一使用者在短時間內發送太多請求，保護後端和資料庫不被過載。

🔑 次要用途：Session 資料暫存

暫時儲存一些頻繁需要的資料，避免每次都去查 PostgreSQL，減少資料庫負擔。

速率限制：如何防止濫用？

想像如果沒有速率限制，惡意使用者可以在一秒內發送 10,000 個請求，把伺服器打垮。速率限制用 Redis 追蹤每個使用者的請求頻率：

Redis 中儲存的速率限制資料（Sorted Set）
rate_limit:user:42 → Sorted Set：{ timestamp1: score1, timestamp2: score2, ... }
rate_limit:ip:192.168.1.1 → Sorted Set：{ timestamp1: score1, ... }（未登入用 IP）
Sorted Set 的每個成員是請求的時間戳，score 也是時間戳
可以用 ZRANGEBYSCORE 快速查出「過去60秒內有幾個請求」

速率限制演算法（滑動視窗）

系統使用「滑動視窗（Sliding Window）」演算法，比固定視窗更精確：

步驟 1：確定使用者身份

如果有 JWT Token → 用使用者 ID 作為 Key
如果沒有登入 → 用 IP 位址作為 Key

步驟 2：把這次請求記錄進 Redis

用 ZADD rate_limit:user:42 [現在時間] [現在時間] 加入一筆記錄

步驟 3：清除過期記錄

用 ZREMRANGEBYSCORE 刪除超過 60 秒的舊請求記錄

步驟 4：計算當前視窗內的請求數

用 ZCARD 計算 Sorted Set 的元素數量（= 過去 60 秒的請求數）

步驟 5：判斷是否超限

如果請求數 > 限制（例如 100 次/分鐘）→ 回傳 429 Too Many Requests
否則 → 繼續處理請求

視覺化範例（限制：100次/分鐘）
第 1-80 次請求
✓ 通過
第 81-100 次請求
✓ 通過（接近上限）
第 101+ 次請求
✗ 429 拒絕
超過1分鐘後，舊記錄被清除，計數重置，請求可以再次通過

實際程式碼（簡化版）

// app/middleware/rateLimit.go
func LimitAPIRequests(limit int, window time.Duration) gin.HandlerFunc {
  return func(c *gin.Context) {
    // 1. 取得使用者ID或IP
    key := getUserKey(c) // "rate_limit:user:42" 或 "rate_limit:ip:x.x.x.x"
    
    now := time.Now().UnixMilli()
    windowStart := now - window.Milliseconds()
    
    // 2. 加入這次請求的時間戳
    cache.RedisClient.ZAdd(ctx, key, redis.Z{Score: float64(now), Member: now})
    
    // 3. 移除超過時間窗口的舊請求
    cache.RedisClient.ZRemRangeByScore(ctx, key, "0", strconv.FormatInt(windowStart, 10))
    
    // 4. 計算當前請求數
    count, _ := cache.RedisClient.ZCard(ctx, key).Result()
    
    // 5. 超限就拒絕
    if count > int64(limit) {
      c.JSON(429, gin.H{"error": "Too Many Requests"})
      c.Abort()
      return
    }
    c.Next() // 繼續執行
  }
}

Redis 連線設定

// app/cache/redis.go
var RedisClient *redis.Client

func ConnectToRedis() {
  RedisClient = redis.NewClient(&redis.Options{
    Addr: os.Getenv("REDIS_HOST") + ":" + os.Getenv("REDIS_PORT"),
    // 預設：redis:6379
  })
}
💡 為什麼要用 Redis 而不是直接用 PostgreSQL 做速率限制？
速率限制需要極低延遲的讀寫（每個請求都要執行）。如果用 PostgreSQL，頻繁的計數操作會拖慢資料庫，影響其他正常查詢。Redis 的記憶體操作在微秒內完成，幾乎不影響效能。
