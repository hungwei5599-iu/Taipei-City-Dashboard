🗄️ 資料庫 (Database)

為什麼用兩個 PostgreSQL、PostGIS 地理擴充如何讓地圖功能成真、資料表如何設計來支撐整個系統。

為什麼用兩個資料庫？

這個系統有兩個完全獨立的 PostgreSQL 資料庫，這是整個架構最關鍵的設計決策之一：

🔧 postgres-manager（設定資料庫）

auth_users

使用者帳號、密碼、權限

dashboards

儀表板名稱、圖標、元件列表

components

元件名稱、描述、更新頻率

query_charts

★ 圖表的 SQL 查詢語句、圖表類型

chat_logs

AI 對話紀錄
特性：資料量小、結構穩定、設定類資料
📊 postgres-data（資料庫）

各種資料表（由 DE 建立）

不固定，每個元件對應一個或多個表

範例：population_by_district

district_name, population, updated_at

範例：air_quality_hourly

station_id, pm25, timestamp, geometry

範例：mrt_ridership

station_name, count, date
特性：資料量大、頻繁更新（Airflow 寫入）
💡 類比：postgres-manager 是「辦公室的員工手冊和組織圖」（穩定、很少改變），postgres-data 是「每天更新的業績報表」（資料多、頻繁變動）。分開管理讓兩者互不干擾。
💡 為什麼要分開？
1. 效能隔離：Airflow 大量寫入資料時，不會影響到使用者登入或設定的查詢速度
2. 獨立備份：可以對資料庫用不同頻率備份（設定庫一天一次，資料庫每小時一次）
3. 獨立擴展：資料庫需要更大空間時，只擴展它，不影響設定庫
4. 安全隔離：即使資料庫被攻破，設定庫（含帳號密碼）還是安全的

postgres-manager 核心資料表

🔑 使用者表（auth_users）

欄位名稱資料型態鍵說明
idBIGINTPK主鍵，自動遞增
nameVARCHAR使用者名稱
emailVARCHARUNIQUE電子信箱（登入帳號）
passwordVARCHAR雜湊後的密碼
tp_uuidVARCHAR台北通 UUID（OAuth 登入用）
is_adminBOOLEAN是否為管理員
is_activeBOOLEAN帳號是否啟用
is_whitelistBOOLEAN是否在白名單（台北市府員工）
is_blackedBOOLEAN是否被封鎖
login_atTIMESTAMP最後登入時間

📋 儀表板表（dashboards）

欄位名稱資料型態鍵說明
indexVARCHARPK儀表板唯一識別碼（如："taipei-01"）
nameVARCHAR儀表板顯示名稱
iconVARCHAR圖示名稱
componentsINT[]★ 包含的元件 ID 陣列（PostgreSQL 陣列型別）

⭐ 最重要：query_charts 表（圖表查詢設定）

這是整個系統的核心設定表。它告訴後端：每個元件要執行哪個 SQL、圖表長什麼樣子。

欄位名稱資料型態鍵說明
idBIGINTFK關聯到 components.id
query_typeVARCHAR資料類型：two_d / three_d / time_series / map_legend
queryTEXT★ 要在 postgres-data 執行的 SQL 語句
chart_typeVARCHAR圖表元件名稱（BarChart / DonutChart 等）
colorTEXT[]圖表顏色設定陣列
unitVARCHAR資料單位（人、輛、%等）
history_configJSONB歷史資料設定（時間範圍、SQL等）
map_configJSONB[]地圖圖層設定（類型、顏色、篩選等）
💡 聰明的設計：「資料」和「如何顯示資料」分開儲存
query_charts 存的是「規則」（要用哪個 SQL 查詢、用哪種圖表顯示），不是資料本身。這樣管理員可以隨時修改圖表樣式或查詢語句，不需要改後端程式碼。

postgres-data 的資料格式

後端查詢資料後，根據 query_type 返回不同格式：

two_d（二維資料）

用於長條圖、圓餅圖、甜甜圈圖

[
  { "x_axis": "大安區",
    "data": 312000 },
  { "x_axis": "信義區",
    "data": 228000 }
]

three_d（三維資料）

用於分組長條圖、百分比堆疊圖

[
  { "x_axis": "大安區",
    "y_axis": "男性",
    "icon": "male",
    "data": 155000 },
  ...
]

time_series（時間序列）

用於折線圖、面積圖

[
  { "timestamp": "2024-01-01",
    "series_name": "大安區",
    "value": 312000 },
  ...
]

map_legend（地圖圖例）

用於地圖圖層，含地理資訊

[
  { "name": "大安區",
    "value": 312000,
    "geometry": {
      "type": "Polygon",
      "coordinates": [...]
    } }
]

PostGIS：讓資料庫懂得「地理」

🌍 什麼是 PostGIS？

PostGIS 是 PostgreSQL 的擴充套件，讓資料庫能夠儲存和查詢地理空間資料（如多邊形、點位、線段）。

-- 儲存行政區邊界（Polygon 多邊形）
SELECT name, ST_AsGeoJSON(geometry) -- 輸出 GeoJSON
FROM district_boundaries
WHERE ST_Contains(geometry, ST_Point(121.5, 25.04)) -- 點在多邊形內？

-- 計算兩點距離（公尺）
SELECT ST_Distance(
  ST_Point(121.5, 25.04)::geography,
  ST_Point(121.52, 25.06)::geography
) AS distance_meters

系統用 PostGIS 儲存台北市各行政區的邊界多邊形，讓地圖可以顯示「區域著色圖」。

// app/models/database.go - 建立連線
func ConnectToDB() {
  managerDSN := fmt.Sprintf(
    "host=%s user=%s password=%s dbname=%s port=%s sslmode=disable",
    os.Getenv("DB_MANAGER_HOST"), // postgres-manager
    os.Getenv("DB_MANAGER_USER"),
    os.Getenv("DB_MANAGER_PASSWORD"),
    ...
  )
  global.MANAGER_DB, _ = gorm.Open(postgres.Open(managerDSN))
  
  // 資料庫連線同理...
}
