# 雙北城市儀表板 - 原型驗證階段資料血緣 (Data Lineage) 盤點報告

本文件盤點 `docs/3-Tracks/prep_compoment/ship/` 內驗證過原型的所有組件，以及獨立驗證的「運動中心使用情況」原型之資料來源與血緣關係。

## ⭐️ 核心追蹤：組件一「運動中心使用情況」

本組件以「雙北運動中心場館設施與人潮」為核心，針對想運動的市民提供視覺化決策輔助，並於複合災難情境下（如大停電、極端高溫）提供避暑避難指引。

### 2. 評審判定與合規性分析 (Judge's Assessment)

**判定結果：高價值 (High Value) / 高技術風險 (High Risk)**

| 檢核維度 | 評審判定 | 深度講評與修正建議 |
| :--- | :--- | :--- |
| **公共決策價值** | ⭐️⭐️⭐️⭐️⭐️ | 從「統計分析 (Observatory)」進化為「即時指揮 (Operation)」。在極端高溫下引導市民避暑，具備極高公共價值。 |
| **資料品質 (Orphan Rate)** | ❌ 高風險 | 分散式網頁資料缺乏統一 ID，Orphan Rate (孤兒率) 高。**建議**：建立靜態點位母表，並以經緯度作為 Join Key。 |
| **資料時效 (Staleness)** | ⚠️ 需警戒 | 爬蟲抓取資料易產生沉默延遲。**建議**：若爬蟲失敗，後端應具備「降級機制」，自動切換回「歷史趨勢 (靜態趨勢)」並標註「模擬數據」。 |
| **大會技術紅線** | ⚠️ 需優化 | 嚴禁前端直連外部網頁。所有 Scraping logic 必須封裝在 **Go Proxy** 層，並輸出為標準 `two_d` 格式。 |

**🏆 評審總結建議**：
這是一個「炫技」與「實務」並存的好題目。為了在黑客松勝出，團隊應將重心放在 **「如果資料斷鏈了，AI 如何透過歷史數據進行『韌性預測』」**。不要執著於抓取 100% 真實即時資料，而應建立一套**「真實爬蟲 + 歷史趨勢 + AI 補償」**的混合模型，這才是政府官員最想看到的「韌性系統」。

### 組件 5：雙北急診即時壅塞度 (validate-component-5.html)

  - **AI 輔助**：可將此作為「災難疏散」劇本的關鍵指標，由 TWCC LLM 決定救護車調度策略 (副作用視覺化)。

## 總結
1. **靜態資料 (基礎設施/點位)**：可輕易從 `data.taipei` 或 `data.ntpc.gov.tw` 的 CSV/JSON 介接。
2. **動態資料 (即時狀態)**：目前大多缺乏官方單一入口 API，這是此黑客松專案正式後端開發階段需解決的核心技術負債。
