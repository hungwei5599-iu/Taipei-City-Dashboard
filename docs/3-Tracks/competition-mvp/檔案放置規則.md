# 檔案放置規則

最後更新：2026-05-01

本文件定義 agents 與人員必須把競賽文件與產出證據放到哪裡。

## 正式 active 路徑

| 產物類型 | 必要路徑 |
|---|---|
| 競賽 MVP 入口 | `docs/3-Tracks/competition-mvp/README.md` |
| PM 規劃與故事文件 | `docs/3-Tracks/competition-mvp/plan/` |
| DE / BE / FE 契約 | `docs/3-Tracks/competition-mvp/contracts/` |
| 個人工作規格 | `docs/3-Tracks/competition-mvp/role-specs/` |
| lane 交接文件 | `docs/3-Tracks/competition-mvp/handoff/` |
| 驗收與稽核清單 | `docs/3-Tracks/competition-mvp/verification/` |
| 歷史證據 | `docs/Archive/2026-hackathon-prep/` |
| 賽前工具原始碼 | `tools/pre-hackathon/` |

## 舊路徑

以下路徑屬於只讀的歷史來源，除非任務明確要求歸檔或修復，否則不要在裡面新增 active 文件：

- `docs/3-Tracks/prep_compoment/`
- `docs/hackathon/`
- `docs/Archive/Data-Source-Old/`
- `docs/Archive/General-Old/`

新的 spec、契約、角色卡、快速驗證報告與原型 HTML 都不得寫到這些位置。

## 產出證據規則

- 快速驗證 Markdown 放到 `docs/Archive/2026-hackathon-prep/validation-reports/`。
- 原型 HTML 放到 `docs/Archive/2026-hackathon-prep/prototype-html/`。
- OMC / OMX / Gemini 的輸出留在 runtime 資料夾，只透過 `docs/Archive/2026-hackathon-prep/tool-artifacts-index.md` 連結。
- Runtime logs、`.DS_Store`、`node_modules`、`venv`、`.venv` 與 `.env` 都不得存到 `docs/` 底下。

## active 文件規則

- active 文件必須描述競賽期間要重建的內容。
- active 文件不得把賽前 prototype code 描述成競賽 code。
- active 文件必須使用絕對日期。
- 每份 role spec 都必須包含 owner、artifact、input、output path、upstream dependency、downstream consumer、done criteria 與 do-not-duplicate。
