# 競賽 MVP 軌道

最後更新：2026-05-01

這是 Taipei Dashdorad 競賽重建策略的正式文件入口。

目標是在競賽期間，從官方 fork 以透明 commit 的方式重建一個乾淨的 4 組件 MVP。既有程式碼、驗證 HTML、快速驗證報告，以及 Gemini / OMC / OMX 輸出都只作為證據，不是可直接複製回競賽儲存庫的原始材料。

## 策略

- 在競賽期間從官方 fork 開始重建。
- 賽前工作只用來提供規格、契約、schema、測試與展示腳本。
- 提交可驗證的單位，不要切成刻意的人為時間片段。
- 保持 AI 可拆除：即使沒有 AI 卡片，儀表板仍要能說明決策。
- 每條 lane 都必須只有一位 DRI 負責。

## 四個 MVP 組件

| 組件 | 用途 | 主要負責人 | 資料格式 |
|---|---|---|---|
| 雙北現況地圖 | Mapbox 空間分布、熱區與區域差異 | FE，在 DE/BE 交接後實作 | `map_legend` / GeoJSON payload |
| 趨勢與異常圖表 | 時間序列或百分比變動，用來表示狀況是否惡化 | FE，在 BE 契約完成後實作 | `time` |
| 台北 vs 生活圈比較卡 | 排名、密度、差距或服務覆蓋率比較 | FE，在 DE/BE 交接後實作 | `two_d` 或 `percent` |
| AI 決策摘要卡 | 以證據為基礎的洞察、風險、建議與副作用 | BE/AI，FE 為消費端 | 結構化 tool output |
