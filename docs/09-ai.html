🤖 AI 功能

AI 聊天機器人如何回答城市相關問題、向量搜尋如何用語意理解找到相關圖表、Tool Calling 如何讓 AI 查詢即時資料。

系統中有哪些 AI 功能？

💬 AI 聊天助手

使用者可以用自然語言詢問城市相關問題，AI 會調用工具查詢即時資料回答。背後使用 TWCC（台灣超級電腦雲）的 LLM。

🔍 向量語意搜尋

使用者輸入關鍵字（如「交通」），系統能找出語意相關的圖表元件，不只是字面上的關鍵字匹配。

AI 聊天流程

當使用者在聊天框輸入問題，系統啟動 AI 對話流程：

對話範例
台北市目前的人口是多少？
👤
🤖
讓我查一下最新的人口資料...
[調用工具: get_population_summary]

Tool result: { "total": 2646204, "year": 2024, ... }
🤖
根據最新資料，截至 2024 年，台北市總人口為約 264 萬 6 千人。與去年相比減少約 1.2%，呈現人口持續下降的趨勢...

Tool Calling（工具調用）是什麼？

LLM 本身只能根據訓練資料回答，無法取得即時數據。「工具調用」讓 AI 能夠執行真實的函式、取得最新資料：

1

後端把「工具清單」告訴 LLM

在呼叫 TWCC API 時，一起傳送可用的工具定義（函式名稱、參數格式、功能說明）

2

LLM 決定是否需要調用工具

如果問題需要即時資料（如「現在的 PM2.5」），LLM 回應「我需要呼叫 xxx 工具」而不是直接回答

3

後端執行工具，取得資料

後端的 tool registry 接收到工具調用請求，執行對應的 Go 函式（如查詢資料庫）

4

把工具結果回傳給 LLM

把工具執行結果加入對話歷史，再次呼叫 LLM，讓它根據真實數據產生最終回答

5

最多重複 5 次（防無限循環）

系統設有最大迭代次數（5次），避免 LLM 不斷要求工具調用造成無窮迴圈

已註冊的工具

// app/services/ai/tools/registry.go
// 系統目前有以下工具可讓 AI 調用

var RegisteredTools = []Tool{
  {
    Name: "get_current_time",
    Description: "取得目前的日期和時間",
    Handler: func() → 回傳目前時間
  },
  {
    Name: "get_population_summary",
    Description: "取得台北市人口統計摘要",
    Handler: func() → 查詢資料庫回傳人口資料
  },
}

// 工具調用流程（最多5次迭代）
for i := 0; i < 5; i++ {
  response := callLLM(messages, tools)
  if response.FinishReason != "tool_calls" {
    break // LLM 直接回答，不需要工具
  }
  // 執行工具，加入結果，繼續循環
  toolResult := executeTool(response.ToolCall)
  messages = append(messages, toolResult)
}

向量搜尋：怎麼理解「語意」？

傳統搜尋是關鍵字匹配（文字要完全相同），向量搜尋理解的是語意相似度：

💡 類比：傳統搜尋像「拼音字典」——查「人口」只找到寫著「人口」的條目。向量搜尋像「理解意思的圖書館員」——問他「城市居民統計」，他知道你要找「人口分布圖」，因為這兩個詞語意相似。

向量搜尋的工作原理

1

建立索引：把每個元件的描述轉成向量

用 ONNX E5 模型把文字描述轉成一個數字陣列（向量），存入 Qdrant 向量資料庫。例如「台北市各區人口分布」→ [0.23, -0.45, 0.78, ...]（768維向量）

2

查詢：把搜尋詞也轉成向量

使用者輸入「交通流量」→ ONNX 模型把它轉成向量

3

計算相似度

Qdrant 計算查詢向量和所有元件向量的「餘弦相似度」（cosine similarity），找出最相似的 N 個

搜尋「交通壅塞」的向量相似度結果
各路段車流量
0.92
捷運乘客人數
0.78
停車場使用率
0.71
台北市人口分布
0.31
空氣品質指數
0.22
相似度 > 0.5 的元件會被回傳給使用者

ONNX：本地端 AI 模型

系統使用 ONNX Runtime 在本地執行嵌入模型，不需要呼叫外部 API 做向量轉換：

// 使用 E5 模型把文字轉成向量（本地執行）
// 模型在 Docker 建構時下載並打包進映像檔

func GenerateEmbedding(text string) ([]float32, error) {
  // 1. Tokenize（把文字切成 token）
  tokens := tokenizer.Encode(text)
  
  // 2. 用 ONNX 模型推理產生向量
  output, _ := onnxSession.Run(tokens)
  
  // 3. 正規化向量（讓長度為1）
  return normalize(output.Embeddings[0]), nil
}
💡 為什麼用本地模型而不是 OpenAI Embeddings？
1. 成本：本地模型零費用，呼叫外部 API 要付費
2. 速度：本地計算無網路延遲
3. 隱私：城市資料不需要傳送到外部服務
4. 穩定：不依賴外部服務的可用性
