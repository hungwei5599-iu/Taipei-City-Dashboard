postgres-manager 完全解析

這個資料庫是整個台北儀表板的「控制中心」—— 它不存放實際圖表數據，而是儲存所有的設定、結構、權限，決定儀表板長什麼樣、誰可以看到什麼、組件要怎麼呈現。

Go Model: DBManager → dashboardmanager 資料庫

它在哪裡？

Docker 服務名稱 postgres-manager
定義檔案 docker/docker-compose-db.yaml
對外 Port 5432:5432（本機 5432 對應容器 5432）
Image postgis/postgis:16-3.4-alpine（支援地理空間運算）
資料庫名稱 dashboardmanager（由 DB_MANAGER_DBNAME 設定）
資料持久化 Docker Volume: postgres_manager_data
Go 全域變數 models.DBManager（在 models/database.go 定義）
BE Schema 初始化 models.MigrateManagerSchema() 使用 GORM AutoMigrate
Sample Data 載入 db-sample-data/dashboardmanager-demo.sql（由 docker-compose-init.yaml 執行）
與 postgres-data 的根本差異：
postgres-data（5433）存放圖表的業務數據（YouBike 站點、人口統計、空污數值...），由 DE/Airflow 定期更新。
postgres-manager（5432）存放系統設定與組件定義，由管理者手動維護。兩者完全獨立，職責分明。

每張資料表詳細說明

components 核心
組件的「名牌」— 只記最基本的識別資訊
欄位型別說明
PK idinteger自動遞增主鍵，FE 和 dashboard 用這個 id 來引用組件
indexvarchar組件的英文唯一代號，例如 youbike_availability，其他表用 index 來 JOIN
namevarchar組件的中文顯示名稱，例如「YouBike使用情況」

為什麼只有三個欄位？

故意設計成最薄的一層，只作為「索引節點」。圖表外觀設定放 component_charts，地圖設定放 component_maps，查詢 SQL 放 query_charts。分開存放讓同一個組件可以跨城市重複使用，只需要在 query_charts 裡加入不同城市的 SQL 即可。

component_charts 核心
圖表視覺設定 — 顏色、圖表類型、單位
欄位型別說明
PK indexvarchar對應 components.index，1對1關係
colorvarchar[]圖表顏色陣列，例如 {"#FF5733","#33FF57"}，多系列圖表各自一個顏色
typesvarchar[]圖表類型陣列，例如 {"bar","line"}，對應 FE 的圖表元件
unitvarchar數值單位，例如 輛、%、人，顯示在圖表旁

為什麼圖表設定要獨立一張表？

同一個組件的圖表外觀設定（顏色、類型）與城市無關，不論臺北或雙北版本，視覺呈現一樣。獨立成一張表可以避免在 query_charts 的每個城市版本都重複儲存相同的視覺設定。

query_charts 核心
組件的 SQL 查詢設定 + 元資料（最重要的表之一）
欄位型別說明
PK index + cityvarchar複合主鍵：同一個組件 index，針對不同城市（taipei / metrotaipei）可以有不同的 SQL 查詢
query_typevarchar查詢類型，例如 three_d（3D圖表）、map_legend（地圖圖例）等，決定 BE 如何處理回傳結果
query_charttext實際的 SQL 語句，BE 執行這個 SQL 來從 postgres-data 取資料
query_historytext查詢歷史時間序列資料的 SQL（可選）
history_configjson歷史資料的時間軸設定（時間格式、間隔等）
map_config_idsinteger[]關聯到 component_maps 的 id 陣列，一個組件可以有多個地圖圖層
map_filterjson地圖篩選設定（例如只顯示某個行政區的資料）
time_fromvarchar資料的起始時間，static 表示靜態資料無時間範圍
update_freqinteger更新頻率數字（配合 update_freq_unit 使用）
update_freq_unitvarchar更新頻率單位，例如 minute、hour、day
sourcevarchar資料來源名稱，例如「交通局」、「主計處」，顯示在組件資訊欄
short_desctext組件的短介紹（FE hover 顯示）
long_desctext組件的詳細說明（FE 展開資訊面板顯示）
use_casetext使用情境說明，說明這個組件適合用在什麼決策場景
linkstext[]資料來源的原始連結陣列
contributorstext[]貢獻者 user_id 陣列，對應 contributors 表的 user_id 欄位
citytext城市識別：taipei 或 metrotaipei（雙北）

為什麼同一個組件要有多個 query_charts 記錄？

台北市（taipei）和雙北（metrotaipei）的資料表結構可能不同，需要不同的 SQL。這個設計讓同一個組件只需要維護一份視覺設定（component_charts），但可以用不同 SQL 對應不同城市的資料來源，非常靈活。

component_maps 核心
Mapbox 地圖圖層設定 — 你要新增的組件會用到這裡
欄位型別說明
PK idinteger自動遞增，被 query_charts.map_config_ids[] 引用
indexvarchar對應 components.index（但一個 index 可以有多個地圖圖層）
titlevarchar圖層的顯示標題，例如「自行車路網」
typevarcharMapbox 圖層類型：circle（點）、line（線）、fill（面）、symbol（圖示）
sourcevarcharMapbox source 類型或名稱，例如 geojson、vector
sizevarchar（可選）圖層大小設定
iconvarchar（可選）Symbol 圖層使用的圖示名稱
paintjsonMapbox paint 屬性，控制顏色、透明度等視覺樣式
propertyjson其他圖層屬性（layout、filter 等）

你的新組件需要在這裡新增一筆

要加 Mapbox 地圖組件，必須在這裡建立一筆設定，定義圖層類型（通常是 circle 顯示點位）和 paint 樣式。然後把這筆記錄的 id 放到 query_charts.map_config_ids[] 裡。

dashboards 核心
儀表板定義 — 組合多個組件成一個頁面
欄位型別說明
PK idinteger自動遞增主鍵
indexvarchar唯一識別碼，用於 URL 路由，例如 ltc_care_tpe
namevarchar儀表板的中文名稱，例如「長照關懷」
componentsinteger[]包含的組件 id 陣列，例如 {214,215,216,218}，順序決定顯示順序
iconvarcharMaterial Icons 圖示名稱，例如 elderly、directions_car
updated_attimestamp最後更新時間

components 為什麼用陣列而不用 JOIN 表？

使用 PostgreSQL 的 integer[] 陣列有個好處：陣列的順序就是組件在儀表板上的排列順序。如果改用中間表，要額外維護 order 欄位。這是一個以可讀性換取彈性的取捨，適合儀表板這種順序重要的場景。

dashboard_groups
儀表板與群組的多對多關聯表
欄位型別說明
PKFK dashboard_idinteger關聯到 dashboards.id
PKFK group_idinteger關聯到 groups.id
這張表決定「哪個儀表板屬於哪個群組」，進而控制哪些使用者能看到哪些儀表板。
例如：group_id=1 是 public 公開群組 → 所有人都能看到。
group_id=2 是 taipei 臺北群組 → 顯示在「臺北儀表板」分類下。
group_id=3 是 metrotaipei 雙北群組 → 顯示在「雙北儀表板」分類下。

群組定義 — 公開群組 + 個人群組

三方關聯：使用者 × 群組 × 角色

這張表是整個權限系統的核心，回答「某個使用者，在某個群組裡，擁有什麼角色？」的問題。

範例：
user_id=5, group_id=2(taipei), role_id=2(editor) → 使用者5是臺北儀表板群組的編輯者
user_id=5, group_id=1(public), role_id=3(viewer) → 同一個使用者5在公開群組只有讀取權限

當使用者登入後，BE 會查這張表取得所有 (group_id, role_id) 對，打包進 JWT token 的 permissions 欄位，前端每次 API 請求都會帶著這份權限清單。

query_type 完整對照表

query_type 是 query_charts 裡最重要的欄位之一，它決定 BE 用哪個函式解析 SQL 結果，進而決定 FE 能顯示什麼圖表類型。

GET /api/v1/components/:id/chart
BE controller 根據 query_type 分派到不同的資料處理函式（componentData.go）
query_type 值BE 處理函式SQL 必須回傳的欄位適合的圖表說明
two_d GetTwoDimensionalData x_axis, data 長條圖、折線圖、面積圖 最基本的二維資料，一個 x 對應一個 y 值
three_d GetThreeDimensionalData x_axis, y_axis, data, icon 分組長條圖、堆疊圖 三維：x 是類別、y 是系列名稱（分組）、data 是數值
percent GetThreeDimensionalData x_axis, y_axis, data, icon 圓餅圖、百分比圖 與 three_d 共用同一個 BE 函式，FE 用不同方式渲染
time GetTimeSeriesData x_axis (timestamp), y_axis, data 時間序列折線圖 x_axis 必須是時間戳記格式，BE 自動轉成 ISO 8601
map_legend GetMapLegendData name, type, icon, value 地圖圖例面板 搭配 component_maps 地圖圖層使用，SQL 回傳圖例清單
時間篩選的魔法： 如果 SQL 裡包含兩個 %s 佔位符，BE 會自動把 FE 傳來的 time_from 和 time_to 填進去，讓組件支援時間範圍篩選。如果 SQL 裡沒有 %s，則每次都回傳完整資料（靜態組件）。

SQL 回傳格式範例

two_d 查詢範例

-- query_type = 'two_d'
SELECT
  district AS x_axis,
  population AS data
FROM public.population_tpe
ORDER BY population DESC

map_legend 查詢範例（地圖組件用）

-- query_type = 'map_legend'
SELECT
  unnest(array['設施位置']) AS name,
  'circle' AS type,
  '' AS icon,
  0 AS value

three_d 查詢範例

-- query_type = 'three_d'
SELECT
  year AS x_axis,
  age_group AS y_axis,
  count AS data,
  '' AS icon
FROM public.age_structure
ORDER BY year, age_group

time 時間序列查詢範例（含時間篩選）

-- query_type = 'time', 含 %s 支援時間篩選
SELECT
  recorded_at AS x_axis,
  station_name AS y_axis,
  aqi AS data
FROM public.air_quality
WHERE recorded_at
  BETWEEN '%s' AND '%s'

關鍵洞察： query_charts 裡的 SQL 是在 postgres-data 執行的，而不是 postgres-manager。postgres-manager 只是「存放 SQL 字串」，真正的計算在 postgres-data 上跑。所以兩個 DB 缺一不可。

BE 核心查詢：五張表如何拼在一起

每次 FE 開啟儀表板，BE 會執行 createTempComponentDB()（位於 Taipei-City-Dashboard-BE/app/models/componentConfig.go），這個函式把五張表串在一起，一次回傳完整的組件資料。

// createTempComponentDB 的邏輯（簡化版）

-- Step 1: 把 components 和 component_charts 合併
subQuery1 = SELECT
  components.id, components.index, components.name,
  row_to_json(component_charts.*) AS chart_config
FROM components
JOIN component_charts ON components.index = component_charts.index

-- Step 2: 把 query_charts 和 component_maps 合併（地圖設定可能有多個）
subQuery2 = SELECT
  query_charts.index,
  query_charts.city,
  json_agg(row_to_json(component_maps.*)) AS map_config
FROM query_charts
LEFT JOIN unnest(query_charts.map_config_ids) AS id_value ON true
LEFT JOIN component_maps ON id_value = component_maps.id
GROUP BY query_charts.index, query_charts.city

-- Step 3: 把以上兩個子查詢再和 query_charts 合併，取得所有欄位
final = SELECT *
FROM subQuery1 AS components
LEFT JOIN subQuery2 AS qc
  ON components.index = qc.index
LEFT JOIN query_charts
  ON components.index = query_charts.index
  AND qc.city = query_charts.city
為什麼 map_config_ids 要用 unnest()？
因為一個組件可以有多個地圖圖層（例如：底圖 + 標記點 + 行政區邊界），這些圖層的 id 以陣列形式存在 query_charts.map_config_ids[] 裡。unnest() 把陣列展開成多行，再用 json_agg() 把所有展開的圖層資料重新收集成一個 JSON 陣列回傳給 FE。

實戰：新增一個帶 Mapbox 地圖的組件

你要加的是一個顯示經緯度點位的地圖組件（例如某個設施的位置）。需要依序在這幾張表寫入資料：

  1. 先在 postgres-data 建立資料表（存放實際的點位資料） 
    CREATE TABLE public.my_locations (
  id      serial PRIMARY KEY,
  name    varchar(100),
  lat     float8,   -- 緯度
  lng     float8,   -- 經度
  address varchar(200)
);
  2. 在 component_maps 新增地圖圖層設定（postgres-manager） 
    INSERT INTO component_maps (index, title, type, source, paint, property)
VALUES (
  'my_location_map',
  '設施位置',
  'circle',                 -- 點狀圖層
  'geojson',
  '{"circle-radius": 6, "circle-color": "#00b4ff", "circle-opacity": 0.8}',
  'null'
);
-- 記住回傳的 id，假設是 120
  3. 在 components 新增組件識別（postgres-manager） 
    INSERT INTO components (index, name)
VALUES ('my_location_map', '我的設施位置');
-- 記住回傳的 id，假設是 300
  4. 在 component_charts 新增圖表設定（postgres-manager，即使是地圖組件也需要這筆） 
    INSERT INTO component_charts (index, color, types, unit)
VALUES (
  'my_location_map',
  '{"#00b4ff"}',
  '{"map"}',               -- 類型設為 map
  ''
);
  5. 在 query_charts 新增 SQL 查詢（postgres-manager，查詢 postgres-data 的語法，需要回傳 GeoJSON 格式） 
    INSERT INTO query_charts (

  'my_location_map',

  '自訂資料',
  '顯示設施位置分布',
  '詳細說明...',
  '使用情境...',
  '{}',
  '{}'
);
  6. 建立新儀表板並把組件放進去（postgres-manager） 
    -- 建立儀表板

VALUES (
  'my_new_dashboard',
  '我的新地圖儀表板',

  'map'                    -- Material icon 名稱
);

-- 把儀表板加入 taipei 群組（讓它出現在臺北儀表板分類）
INSERT INTO dashboard_groups (dashboard_id, group_id)
VALUES (
  (SELECT id FROM dashboards WHERE index = 'my_new_dashboard'),
  2                       -- group_id=2 是 taipei 群組
);
完成以上 6 步後： 重新整理前端，你的新儀表板就會出現在「臺北儀表板」分類下，點進去會看到地圖組件，地圖上會顯示 postgres-data 裡的點位資料。

如何連線查看這個資料庫

方法一：pgAdmin（已包含在 docker-compose-db.yaml）

啟動後開啟 http://localhost:8889，登入後新增一個 Server：

Hostpostgres-manager（Docker 網路內部名稱）
Port5432
Databasedashboardmanager
Username${DB_MANAGER_USER}（.env 裡設的）
Password${DB_MANAGER_PASSWORD}

方法二：從本機直接 psql 連線

因為 docker-compose-db.yaml 把 5432 對外開放，可以直接從本機連：

psql -h localhost -p 5432 \
     -U postgres \
     -d dashboardmanager

方法三：進入容器

docker exec -it postgres-manager \
  psql -U postgres -d dashboardmanager
