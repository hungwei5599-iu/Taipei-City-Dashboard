🗺️ 整體架構概覽

從最高視角理解台北城市儀表板——這個系統由哪些部分組成、它們如何協作、資料如何從原始來源流到你的螢幕上。

這個系統在做什麼？

台北城市儀表板（Taipei City Dashboard）是由台北市政府智慧城市研究院（TUIC）開發的開放原始碼公共資料視覺化平台。它的核心目標很簡單：

  • 把台北市各種即時資料（交通、空氣、人口、災情等）集中在一個地方
  • 用圖表和地圖讓市民和政策制定者一眼就能理解現況
  • 讓任何人都可以自訂儀表板，關注自己在意的指標
💡 類比：把這個系統想成一個「城市健康檢查中心」。體檢機器（資料工程）持續收集數據，醫療記錄系統（資料庫）儲存所有數據，護理師（後端）整理資料給你看，螢幕顯示器（前端）讓你看到漂亮的圖表。

三個核心部分

🖥️ 前端 (FE - Frontend)

使用者看到和操作的介面

  • Vue 3 + Vite 建構的 SPA 應用
  • ApexCharts 畫圖表
  • Mapbox GL + Deck.gl 畫地圖
  • Pinia 管理狀態（資料）
  • Axios 向後端發送請求

⚙️ 後端 (BE - Backend)

資料的中間人和守門員

  • Go + Gin 框架的 REST API
  • 處理認證（JWT/OAuth）
  • 查詢 PostgreSQL 取得資料
  • Redis 做速率限制
  • AI 聊天服務整合

🔄 資料工程 (DE - Data Engineering)

自動化資料處理管道

  • Apache Airflow 排程管理
  • Python 腳本抓取外部 API
  • 資料清洗和轉換
  • 寫入 PostgreSQL 資料庫
  • Celery + Redis 分散式執行

🏗️ 基礎設施

把所有東西放在一起運行

  • Docker 容器化每個服務
  • Docker Compose 協調啟動
  • Nginx 做反向代理和路由
  • PostgreSQL x2 + Redis + Qdrant
  • Helm Chart 支援 Kubernetes 部署

資料如何流動：一個圖表的誕生

以「台北市各行政區人口分布長條圖」為例，追蹤資料從哪裡來、怎麼到達你的螢幕：

1

資料工程蒐集原始資料

Airflow DAG 每天自動執行，呼叫政府開放資料 API，取得各區人口數字。Python 腳本清洗資料格式，存入 postgres-data 資料庫的特定資料表。

2

後端定義查詢

postgres-manager 資料庫存有「元資料」：這個圖表叫什麼、要執行什麼 SQL 語句、圖表類型是長條圖。後端啟動時就讀取這些設定。

3

前端發出請求

使用者打開儀表板，Vue 前端向後端發送 GET /api/v1/component/123/chart，附上 JWT token 表明身份。

4

後端處理請求

Gin 框架接收請求 → 中介軟體驗證 JWT → 控制器從設定資料庫查到 SQL 語句 → 執行查詢到資料庫 → 格式化成 JSON 回傳。

5

前端渲染圖表

Axios 收到 JSON 資料，存入 Pinia store，ApexCharts 元件讀取資料，在畫面上畫出長條圖。使用者看到圖表！

Docker 如何把一切組合在一起

整個系統用 Docker Compose 管理，每個服務都是一個獨立的容器（container），就像一個個裝在不同盒子裡的服務：

📦 dashboard-fe
Node.js 容器
建構並服務前端
Port: 8080
📦 dashboard-be
Go 容器
API 伺服器
Port: 8080
📦 nginx
Nginx 容器
反向代理
Port: 80/443
📦 postgres-data
PostgreSQL 容器
圖表資料
Port: 5432
📦 postgres-manager
PostgreSQL 容器
設定/使用者資料
Port: 5433
📦 redis
Redis 容器
快取/速率限制
Port: 6379
所有容器在同一個 Docker 網路 br_dashboard (192.168.128.0/24) 中互相通訊
💡 為什麼要用 Docker？因為每個服務需要不同的環境（Go、Node.js、Python、PostgreSQL），Docker 讓每個服務在自己的「沙盒」中運行，互不干擾，而且可以在任何機器上一鍵啟動整個系統。

Nginx 的角色：門口的警衛和交通指揮員

當瀏覽器向 http://localhost 發送請求時，Nginx 扮演路由的角色：

瀏覽器請求 → Nginx (port 80)

GET / → 轉發到前端 (dashboard-fe:8080)
GET /api/v1/... → 轉發到後端 (dashboard-be:8080)
GET /api/dev/... → 轉發到後端 (dashboard-be:8080)

// Nginx 就像餐廳前台：客人（瀏覽器）來了，
